# rqdx3.v: RQDX3 (DU0–DU3, four RD54) for the KDF11 FPGA project

This is the project-integrated version of rqdx3. It contains its own **sdspi** instance
The MSCP/UQSSP core is the same logic that was cross-checked against simh. Only the outer interfaces
changed. Initial version of the project is generated by Claude.

```
rtl/rqdx3.v          controller (instantiates sdspi)
rtl/rqdx3_defs.vh    constants from pdp11_uqssp.h / pdp11_mscp.h / pdp11_rq.c
tb/tb_rqdx3.v        testbench: real sdspi.v + SPI SD-card model + DMA/interrupt models
tb/sdcard_model.v    SPI SDHC card: CMD0/8/55/ACMD41/17/24, error injection
tb/sectorbuf_model.v behavioural 'sectorbuf' (Quartus RAM) for simulation only
xchk/                simh cross-check: script, logs, result
```
**Interfaces follow the project conventions of forth32 dvk-fpga project**

**Card layout (bank 0):** LBN *n* of unit *u* = card block `start_offset + u × STRIDE + n`.
Parameters: `UNITS` (1–4, default 4) and `STRIDE` (default 0x50000). Each unit uses 311 207
blocks (311 200 data + 7 RCT). The rest of its 0x50000-block slot is unused, the same way DB uses
341 088 blocks of a 0x60000 slot. Zero-fill the 7 RCT blocks (LBN 311200–311206) of each unit.

| Unit | Start (hex / dec) | End (hex) | Used up to (hex) |
|------|-------------------|-----------|------------------|
| DU0  | 000000 / 0        | 04FFFF    | 04BFA6           |
| DU1  | 050000 / 327680   | 09FFFF    | 09BFA6           |
| DU2  | 0A0000 / 655360   | 0EFFFF    | 0EBFA6           |
| DU3  | 0F0000 / 983040   | 13FFFF    | 13BFA6           |

With `start_offset` = 0 this is bank 0 from block 0. To move the DU set into a bank later,
drive `start_offset` with the bank base (for example 0x400000 for bank 1).

## Multiple units (behaviour as simh with RQ0–RQ3 enabled)

- Units 0…UNITS-1 exist; a higher unit number gets ST_OFL.
- Each unit has its own online state and unit flags (AVL/ONL/SUC/write-protect are per unit).
- GUS with "next unit" beyond the last unit wraps to unit 0 (and sets the unit field to 0).
- Unit identifier = unit number; volume serial number = 01234 + unit, as in simh.
- Still one command at a time, so a transfer on one unit holds back commands for the others.
  That's fine for correctness; it only costs parallelism.

## Changes relative to rqdx3

- Outer interfaces replaced as above. The internal sector RAM and block engine were removed in
  favour of sdspi's own buffer and handshake (start / io_done / idle / error, as rk11 uses them).
- `blk_present` and `blk_wp` are gone. The unit is always present and writeable, like the RK05 in
  rk11, so the testbench and cross-check no longer cover "no volume" and "hardware write lock".
- **Descriptor read order fixed (applies to rqdx3 too).** Testing with the real SD timing
  exposed a race. The controller read a ring descriptor's address word, the host then wrote
  address + OWN, and the controller read OWN=1. It combined a stale address with a fresh OWN bit
  and took a fatal packet-read NXM. The controller now reads the high word (OWN) first and the
  address second. Because the host always writes the address before setting OWN, this order is
  safe. simh never sees the race because it reads both words in one step.

The remaining deviations from simh are unchanged from rqdx3: no error-log datagrams, no AVA
attention, no host-access timer, one command at a time (GCS = 0, ABO no-op), per-sector byte count
on drive errors, and a WRITE whose first word is NXM is answered (simh never responds to it).
